経営管理Webアプリ UI/UX改修指示

対象：キャッシュフロー管理・案件管理

目的

既存の経営管理Webアプリを、洗練されたSaaSと経営シミュレーションゲームの楽しさを融合したデザインへ改修する。

デザインコンセプトは「経営を、もっと面白く。」

子どもっぽいゲーム表現は避け、上質で直感的なビジネスアプリに仕上げる。

最重要制約

* 既存のデータベース、保存済みデータ、API、計算ロジックを変更しない。
* 既存機能を削除しない。
* 入出金予定、実績、売上計画、案件ステータス、請求・入金状態の意味を変更しない。
* データを仮の数値で置き換えない。
* 既存の表示条件、権限、操作後の更新処理を維持する。
* UIの変更に必要な範囲以外のリファクタリングを行わない。
* 未実装の機能を動作するように見せない。
* 変更前に既存のコンポーネントとデータ依存関係を調査する。

1. キャッシュフロー管理

1-1. ヘッダー

* ページタイトルと月選択をコンパクトに配置する。
* キャッシュフロー／交通費台帳の切替は維持する。
* 実績入力、入金予定、出金予定、領収書から登録、その他の全操作を維持する。
* 最重要の登録操作を主ボタンとして強調する。
* その他の操作は「追加・操作」メニュー等に整理する。
* メニュー内の項目名を明確にし、既存の処理をそのまま呼び出す。

1-2. 資金状況ヒーローカード

* 現在の口座残高と月末予測残高を最上部の主要カードにまとめる。
* 月末予測残高を最も目立つ金額として表示する。
* 既存の残高入力機能を維持する。
* 現在残高と予測残高の関係を視覚化する。
* 計算式と対象期間は既存仕様を維持する。
* 予測の内訳を確認できるようにする。

1-3. 入出金KPI

* 実績入金、実績出金、入金予定、出金予定を2列×2行で配置する。
* 各カードにアイコンと金額を表示する。
* 色だけに依存せず、必ず項目名を併記する。
* 金額は桁区切りを付ける。
* タップ時に関連明細へ移動できる場合は、既存の絞り込み処理を利用する。

1-4. 計画対実績

* 現在の縦長カードを、項目別のコンパクトな進捗表示へ変更する。
* 売上、経費合計、役員報酬、税金・公課など既存の全項目を維持する。
* 計画額、実績額、差額を確認できるようにする。
* 収入と支出では差額の評価基準が異なるため、単純にプラスを緑、マイナスを赤としない。
* 実績ゼロを必ずしも異常扱いしない。
* 計画ゼロの項目でゼロ除算を発生させない。

1-5. 入出金明細

* 大型カードをコンパクトなリスト形式に変更する。
* 日付、取引名、種別、金額、予定・実績を一覧表示する。
* 詳細展開時に既存の補足情報を表示する。
* 実績変換、編集、削除などの操作を維持する。
* 削除は誤操作防止の確認処理を維持する。
* CSV出力機能を維持する。
* 明細数が多い場合でもスクロールしやすい構成にする。

2. 案件管理

2-1. 営業サマリー

* 月間売上合計を大きく表示する。
* 対象案件数、商談中件数、売上見込みを整理する。
* 確定売上と売上見込みを明確に区別する。
* 既存の集計対象条件を変更しない。
* 新たな目標値や予測値を捏造しない。

2-2. 案件一覧

* 案件カードの高さを削減する。
* 案件名、顧客名、金額、案件ステータスを優先表示する。
* 期間、種別、請求状態、対象月は補助情報として整理する。
* 入金確認などの主要アクションを明確にする。
* その他の操作は詳細表示またはメニューへまとめる。
* 既存の検索、絞り込み、一括操作、案件追加を維持する。
* 終了案件の表示切替も維持する。
* 繰越や未入金の警告を省略しない。

2-3. 進捗の可視化

* 既存の案件ステータスに応じた進捗表現を検討する。
* ステータスに順序が定義されている場合のみステップ表示を採用する。
* 契約・完了などの状態変化に軽いアニメーションを追加する。
* 存在しない工程や架空の達成率を追加しない。
* 進捗表現によって請求・入金状態を誤認させない。

3. 共通ビジュアル

* 背景：#F8FAFF
* カード：#FFFFFF
* 文字：#17233D
* 補助文字：#64748B
* メインブルー：#3976F6
* パープル：#8758F5
* 成功：#10B981
* 注意：#F59E0B
* 危険：#F43F5E

角丸16〜20pxを基本とし、淡いシャドウ、適度な余白、柔らかなグラデーションを使用する。

スマートフォンでは主要KPIを2列表示し、一覧は縦方向に整理する。

タップ領域は原則44×44px以上を確保する。

4. アニメーション

* 数値更新時は控えめなカウントアップ。
* カードタップ時は軽い反応。
* 進捗表示は自然なトランジション。
* メニューと詳細展開は150〜300ms程度。
* prefers-reduced-motionを尊重する。
* アニメーションがデータ更新や入力操作を妨げないようにする。

5. 実装・検証手順

1. 現行コードの構造、データ取得、状態管理、計算処理を確認する。
2. 変更対象を表示コンポーネントとスタイルに限定する。
3. 共通カード、バッジ、ボタン、明細行のデザインを統一する。
4. キャッシュフロー管理を改修する。
5. 案件管理を改修する。
6. モバイルとPCの表示を確認する。
7. 既存の登録・編集・削除・実績変換・入金確認・CSV出力をテストする。
8. 改修前後で同一データの集計結果と表示値が一致することを確認する。

既存機能・データ・計算結果を完全に維持したまま、視認性、操作性、統一感、経営の進捗を実感できる体験を向上させること。
