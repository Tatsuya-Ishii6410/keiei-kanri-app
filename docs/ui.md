## UI（サイドバー型レイアウト）
- メインカラー：ネイビー --navy #1a2e4a ／ アクセント：オレンジ --orange #E8832A
- 構造：.app > (.sidebar[fixed] + .main) 、.main > .topbar + .content
  サイドバー幅220px。.main は margin-left:220px で逃がす
- ナビは .nav-btn。DOM順は ダッシュボード/案件/見積請求/収支/CSV/レポート/設定。
  goToInvoiced() が querySelectorAll('.nav-btn')[1]、goToPlannedIn() が [3] を
  使うので順番を変えないこと
- ページ名は PAGE_TITLES を見て topbar-title に出す
- 768px以下はサイドバーを隠し、トップバーの「☰ メニュー」で toggleSidebar()
- 同期表示はトップバーとサイドバー下部の2箇所（save-indicator / save-indicator-side）
- グラフ：売上=オレンジ／営業利益=ネイビー／利益率=グリーン
- 入金待ちカードは .metric-card.accent（オレンジ背景・白文字）

## レスポンシブ
- ブレークポイントは 768px（タブレット）と 480px（スマホ）
- 768px以下：サイドバーをスライドイン式に、表とタブを横スクロール、
  ボタン min-height:44px、入力欄 font-size:16px（iOSの自動ズーム防止）
- 480px以下：メトリクスカードとフォームを1列、セレクトとボタンを縦積み、
  表内の操作ボタンを縦積み、見積・請求の一覧は番号と顧客の列を隠す
- 表を潰さず横スクロールさせるため .table-wrap table{min-width:560px}
- 見積・請求のタブは .tab-full / .tab-short で表記を切り替える

## フォント
- Google Fonts の Inter（数字・欧文）と Noto Sans JP（和文）を読み込む
- --font-body（本文）／--font-ja（和文）／--font-num（数値）の3変数で使い分ける
  --font-num は 'Inter','Noto Sans JP',sans-serif。Interに和文グリフが無いため
  Noto を続けて指定し、和文が入る箇所（バッジなど）でも崩れないようにしている
- 見出し・数値・th・合計行は 700、ラベルとナビは 500、本文は 400
- 帳票（buildDocHtml）はダウンロード後も同じ見た目にするため、
  CSS変数ではなく DOC_NUM_FONT の実名フォントを使い、
  ダウンロードするHTMLにも Google Fonts の link を入れている

  ★ body に付ける状態クラスは、接頭辞 bs-（body state）の専用名にする（例 bs-nav2）。部品・画面のクラスと同じ名前は使わない
    （衝突は2回起きた：.dash-v2 の中の .main がアプリの外枠 .main と衝突／body に tb-new を付けて .tb-new{display:none} が body に効き画面が消えた）
    ※ dv2-on は規則より前に作ったもの（そのまま使っている）
- .tb-new（bs-nav2 のとき表示）：≡（スマホだけ。aria-label「メニュー」・toggleSidebar）／タイトル（PAGE_TITLES のまま。長ければ「…」）／
  同期の状態 #tb-sync／ロック #tb-lock（開いた鍵の線画。logout()＝確認のあとログアウト）
  .tb-v2（dv2-on のときだけ）：ベル・アバター・スクロール後の月チップ（新ダッシュボード固有。変更なし）
- 同期の状態は setSyncStatus がそのまま決める（判定は変えていない）。#tb-sync に is-ok／is-sync／is-off／is-err を付けるだけ：
  同期済み＝緑の点 8px（#10B981）／同期中・ローカル保存＝灰色の点（#64748B）／同期エラー＝赤の文字「同期エラー」（#DC2626）。aria-label に状態の名前
  新ダッシュボードではあいさつ行に出すので #tb-sync は出さない
- 旧ヘッダー（☰ メニュー・保存状態・🔓 ログアウト）は旧ダッシュボードでだけ見える（要素は残してある）
- 見た目：56px＋safe-area-inset-top、sticky、白、下の線 rgba(23,35,61,.06)、スクロールしたときだけ薄い影（.is-scrolled）。

## 一覧の上の操作エリア（.list-toolbar。案件管理・CF管理・交通費台帳・月次レポート）
- 構造：.section-header > h1.section-title.title-dup ＋ .list-toolbar > .lt-filters（.lt-select＝select＋シェブロン）＋ .lt-actions
  （.lt-wide＝PCだけのボタン／.lt-primary＝主ボタン／.lt-menu-wrap＝「一括操作 ▾」などのボタンとメニュー .lt-menu）
- PC・タブレット（481px以上）は従来の横並びのまま（中の枠は display:contents。メニューは出さない）
- スマホ（480px以下）：2列のグリッド（高さ44px・角丸12px・間隔8px。select は自作のシェブロン）
  メニューの項目は、PCのボタンと同じ関数を呼ぶ（ltMenu(null);関数()）。外側のタップ・Esc で閉じる、↑↓で移動、Tab で閉じる（ltMenu）
- .lt-flat（CF管理・交通費台帳・月次レポート）：PCの枠（div）はそのまま残し、スマホだけ中の div をほどいて1つの2列グリッドにする。
  行の順は .lt-o1〜.lt-o6 の order で決める（DOMの順はPCのまま）。.lt-o9 は全幅の行（ledger-summary・通年の注記。空なら隠す）
  ★ .lt-menu-wrap は直下にあってもほどかない（>div:not(.lt-menu-wrap)）。.lt-menu-left は左の列のメニュー（左端にそろえる）
- 絵文字：スマホで見えるボタンとタブの絵文字は .lt-emoji に入れ、480px以下で隠す。PCは display:contents（flex の gap が入らず見た目は従来のまま）
- .title-dup：上のバーとタブで画面が分かる見出しに付ける。768px以下で隠す（案件管理・キャッシュフロー管理・レポート）
- 各画面のスマホの並び
  案件管理：［入金ステータス］［月］／［＋案件追加］［一括操作 ▾：一括請求書作成・一括ステータス変更］
  CF管理：［月］［＋実績入力］／［＋入金予定］［＋出金予定］／［領収書から登録］［その他 ▾：ドライブから取込・取込待ち・デビット通知から取込・固定費管理］
    取込待ちが1件以上なら「その他 ▾」とメニューの「取込待ち」に件数（.lt-count[data-inbox-count]。renderInboxStatus が inboxItems.length を入れる）
  交通費台帳：［月］［＋交通費を追加］／［カレンダーから作成］［交通費精算を追加］／［その他 ▾：CSV出力・PDF出力・旧「電車・バス」の手段を整理］
  月次レポート：［月］［レポートを生成］／［出力 ▾：印刷する・月次PL（Excel）をダウンロード］［税金を試算する］。通年モードでは月次PLの項目も隠す（onReportMonthChange）

  見積・請求：［月］（左50%。見出し「見積・請求管理」はタブで分かるので隠す）／請求書タブ：［状態］［＋請求書作成］／［その他 ▾：ドライブから請求書を同期・一括請求書作成］

## スマホの「横長」ルール（全画面。PC＝481px以上は変えない）
1. ボタンは全幅にしない（全幅はフォーム・モーダルの保存・キャンセルと、空の状態の唯一の操作だけ）
2. 1行に最大2個。3つ以上は「その他 ▾」（.lt-menu）。3. 出力（印刷・CSV・Excel・PDF）は「出力 ▾」
4. セレクトは左寄せ・幅50%（.lt-select）か、主ボタンと同じ行。5. 数値カード（.metric-grid。ダッシュボード以外）は2列（1枚だけなら全幅）
6. ボタン・タブ・メニュー項目の絵文字はスマホで隠す（wrapLeadEmoji）。7. 上のバー・タブで分かる見出しは .title-dup で隠す
8. ボタンは高さ44px・角丸12px・間隔8px
- スマホのカードの操作（.mob-card-actions。PCの表には出ない）：mobActions(html) が、3つ以上なら主な1つ（primary・success、無ければ最初の危険でないもの）＋
  「その他 ▾」にまとめる。メニューの項目は元のボタンと同じ onclick（ltMenu(null) のあと）。削除は赤の文字、無効のボタンは無効のまま
  案件カードは「入金確認」（請求済のとき）か「編集」が主。収支カードは「実績に変換」（入金予定のとき）が主。請求書カードは下書きなら「発行」、発行済みなら「表示」
- 実測（375px、上部〜最初のコンテンツ）：見積・請求 183→193px（月のセレクトを44pxにしたため10px増）／CSV取込 178→149／案件予実 251→209／月次締め 214→132／
  その他は変化なし。数値カード：CF管理 430→152px（1枚 98→72）／融資力診断 計1616→830px／案件予実 512→222px
- 直していないもの：設定（保存ボタンはフォームの保存なので全幅のまま。「初期の文面に戻す」も保存と縦に並ぶまま）／CF管理の「前月の請求済み案件を入金予定にする」（カードの中の唯一の操作で全幅ではない）／
  CSV取込の種別ボタン（操作ではなく選択）
- ※ 月次レポートの月の初期値：initReportPage は「select が空なら前月」と書いてあるが、select は最初から「1月」が選ばれていて空にならないため、
  いつも1月（期の並びでは翌年1月）になる。累計（fiscalTotals）は選んだ月までの案件売上（未来の月は契約の予定額）を足し、経費は実績だけなので、
  未来の月を選ぶと確定と予定の区別なく売上が入り、利益が大きく出る（直すかは確認中）

## 編集・追加の画面（モーダル）の3層：見出し／本文（スクロール）／固定フッター
- 交通費の入力（te-modal）と同じ構造を、ほかのモーダルにも起動時に付ける（mfLayoutModals）。条件：.modal の最初の子が .modal-header。最後の子が .actions-row ならフッター（.mf-foot）に固定、無ければ見出しの固定と本文（.mf-body）のスクロールだけ
- 要素は移すだけ（id・onclick・入力値・保存・検証・保存後の更新・閉じ方［✕・背景のタップ・戻る］は変えない）。新しいモーダルも「見出し → 中身 → 最後に .actions-row（キャンセル｜保存）」で書けば自動で3層になる
- 高さは 100dvh から余白と safe-area-inset-bottom を引いた値。フォーカスした欄は .mf-body の中で見える位置へ（focusin → scrollIntoView）
- スマホ（480px以下）でもフッターは横に並べる（キャンセル｜保存）。フッターに削除などの危険な操作は置かない（削除は一覧の行の中・確認つき）。請求書の取消（modal-invoice-cancel）は、取消そのものが主の操作
- 領収書から登録（#rc-body の中のボタンの行）は、本文の中で下に貼り付ける（position:sticky）
- 対象外：設定ページ（カードごとに保存ボタンが7つあり、1つの固定フッターにできない）、選ぶ画面（類似データ・締めの一覧・入金遅延）
