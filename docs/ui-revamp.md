# UI改修（共通部品で CF管理・交通費台帳・案件管理・見積・請求）

ユーザーの指示（2026-11-03）。元の「CF管理・案件管理のUI/UX改修指示書」の本文は、まだ受け取っていない。
「最重要制約」は、この指示の要約（計算・データ・API・既存機能・意味を変えない。数値は変更の前後で一致させる）で守る。

## 方針
- 共通部品を先に作る：資金状況・要約のヒーローカード／2列のKPIカード（アイコン＋項目名＋金額）／コンパクトな明細の行（タップで詳細を展開）／項目別の進捗行／バッジ
- 入出金明細と交通費台帳は、どちらも台帳の1行なので、同じ「行」の部品を使う
- 実装済みの項目は再利用・維持：.list-toolbar と「その他 ▾」メニュー、全画面共通ヘッダー、CF管理のKPIの2列、案件管理の「終了した案件も表示」・繰越・終了日未設定の印、見込みタブ

## 追加の指定
- 口座残高の入力欄：桁区切りで表示（保存する値・保存の処理は変えない）
- ヒーローカード：月末予測残高を最も大きく。現在残高との関係を1本の横棒で視覚化（計算式・対象期間は既存のまま）。内訳（口座残高＋実績＋予定）は展開で見る
- 交通費台帳：要約カード（月の交通費合計・件数・精算状況・精算予定日）と、コンパクトな行（日付・区間・訪問先・用件・金額。要編集の印）。交通費はCFの実績から除外・翌月25日に精算、の仕様は変えない
- 入出金明細・交通費の行：展開で既存の補足情報。編集・削除（確認つき）・実績変換・CSV出力を維持
- 計画対実績：差額は緑・赤で決めつけない（中立の色＋▲▼と数値）。計画ゼロでゼロ除算を出さない
- 絵文字は使わない（線画SVG）。アイコンは KPI の項目名の横に1つまで
- 小さな文字・バッジの赤は #DC2626。タップ領域44px以上。prefers-reduced-motion を尊重

## 共通部品（段階0で追加・7b1de8c。keiei-kanri.html の fmt の直後と、CSS の .app-toast の直後）
- 表示だけの関数。計算・データ・S は触らない。文字は escAttr で escape（…Html の引数は呼び出し側で安全にする）。テスト：tests/ui-common.test.js
- `ucHero({label,value,sub,barHtml,moreHtml})`：value を最も大きく（負は #DC2626）
- `ucBar(基準,結果,基準の名前,結果の名前)`：1本の横棒（灰＝基準、青＝増え、斜線＝減り）。負は幅0で描き、凡例は元の数字
- `ucMore(見出し,[[項目,値]],extraHtml)`：<details> の展開（内訳など）
- `ucKpis([{icon,label,value|valueHtml,id}])`：スマホ2列・PC（1024px〜）4列。アイコンは項目名の横に1つまで（UC_ICONS の線画SVG）
- `ucRow({main,sub,amount,amountClass,amountNote,markHtml,bodyHtml,actionsHtml,attrs})`：台帳の1行（入出金明細・交通費で共通）。<details> でタップ展開。summary は高さ44px以上
- `ucProgress(label,value,max,rightText)`：max≦0 は 0%（ゼロ除算なし）
- `ucBadge(text,tone)`：tone なし／'alert' は赤 #DC2626、ほかは既存の .badge-*
- `ucDiff(実績,計画)`：中立の色＋▲▼＋金額。計画ゼロでは率を出さない
- 動き：transition は付けていない。prefers-reduced-motion の指定も入れてある

## 現状の調査（段階0）
- CF管理（#cf-pane-main・renderLedger）：残高入力 #cf-balance（type=number）、月末予測 #cf-forecast（式＝口座残高＋実績入金−実績出金＋入金予定−出金予定）、metric-grid の4枚（実績入金・実績出金・入金予定・出金予定）、計画vs実績の表（差異を緑・赤で色分け → ucDiff に置き換える）、明細は PC の表 #ledger-list ＋スマホのカード cfCardHtml
- 交通費台帳（renderTravelLedger）：#tl-summary（合計・件数・要編集の件数・精算状況）、PC の表 travelDayRowsHtml ＋スマホ travelDayCardsHtml。全期間は月ごとの見出し＋小計
- 案件管理（renderProjects・projectCardHtml）：状態は 商談中→契約済→進行中→完了（失注は分岐）。ステップ表示は 商談中〜完了 の4つに限り、失注はバッジ
- 見積・請求（renderQuotes・renderQuoteTable・quoteCardHtml）：請求の状態 INVOICE_STATES は 未請求→請求済→入金済（入金済（手動）は入金済と同じ段）
- 絵文字が多い（ボタン・タブの lt-emoji、🔁 など）。各段階で、その画面の分だけ線画SVGか文字にする
- 案件管理の上部：#project-total（売上合計）・#project-total-sub（対象件数）・#project-forecast（売上見込み）・#project-forecast-sub（商談中件数）が既にある。絞り込みは入金状態・月・終了案件の表示。文字の検索欄は無い（足さない）
- CF管理の明細：絞り込みは月だけ（種別・予定/実績の絞り込みは無い）→ KPI のタップで明細へ移る機能は作らない（無い機能を動くように見せない）
- 削除は deleteLedger の confirm を維持。CSV は exportLedgerCsv・exportTravelCsv

## 段階1 CF管理（済）の決めごと
- スマホの明細は cfRowHtml（ucRow）。PCの表は維持（もともと1行が低い）。行の操作（実績に変換・編集・削除）は展開の中。削除の確認は deleteLedger のまま
- ヒーロー：#cf-hero（外枠は静的。中身 #cf-forecast は ucHeroInner）。残高の入力は type=text・inputmode=numeric、表示は桁区切り、cfBalanceRaw で数字だけに戻してから saveBankBalance
- KPI：#cf-kpis に初回だけ ucKpis、以後は ucCountUp で金額だけ更新（id は cf-actual-in など従来のまま）
- LEDGER_STATES の「📅 予定」は CSV 出力でも使うので定義は変えず、画面に出す所だけ外す
- 前後の比較：tests/ui-shot.js（見本のデータ・使い捨てのプロフィールのヘッドレス Chrome。本番サイトは開かない）

## 段階3 案件管理（済）の決めごと
- 営業サマリー #pj-hero：id（project-total・project-total-sub・project-forecast・project-forecast-sub）は従来のまま。確定（契約済・進行中・完了）と見込み（商談中）を枠で分け、見込みは確定の合計に含めないと明記
- スマホの一覧 projectRowHtml（ucRow）。印（繰越・終了・終了日未設定）は footHtml で閉じた行にも出す。操作は mobActions（主な1つ＋その他）。月次請求を開いた案件は開いたまま描く
- `ucSteps(steps,current,label,changed)`：順序のある状態のステップ。current が順序の外なら空（失注はバッジ）。達成率は出さない。changed の時だけ今の段に uc-pop（reduced-motion で止める）
- 見込みタブ・PCの表は変えていない（絵文字だけ外した）

## 段階4 見積・請求（済）の決めごと
- 指示書に見積・請求の節は無い → 段階1〜3の部品と原則（要約・コンパクトな行・状態は別のバッジ・絵文字なし）を当てた
- 要約 #estimate-hero・#invoice-hero（ucHeroInner）。#estimate-summary・#invoice-summary は一覧の見出し（「請求書の一覧（n件）」）に変えた
- スマホの一覧 quoteRowHtml（ucRow）。取消の行は data-cancelled で薄く。期限超過は uc-badge-alert（#DC2626）
- 撮影の突き合わせに、PCの表の行の数とバッジの文字の数え上げ（rows・badges）を足した

## 段階4.5 PC幅の微調整（済）
